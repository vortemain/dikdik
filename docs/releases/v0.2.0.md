# Dikdik 0.2.0 — desktop developer preview

Dikdik now has a native desktop host, animated brand opening, built-in interactive
browser sessions, native notifications and a redesigned terminal. This release
also includes the combined agent, provider, context and responsiveness changes.

## Downloads and installation

- **Windows x64:** run `Dikdik-0.2.0-Windows-x64-Setup.exe`. Requires the Microsoft
  Edge WebView2 Runtime. Installs into the per-user Programs directory.
- **macOS:** open the DMG matching its named CPU architecture and drag Dikdik to
  Applications. This preview is not Developer ID signed or notarized; standard
  Gatekeeper restrictions apply. Native notification permission is required.
- **Linux amd64:** install `Dikdik-0.2.0-Linux-amd64.deb` with
  `sudo apt install ./Dikdik-0.2.0-Linux-amd64.deb`. Targets Ubuntu 24.04 and newer
  compatible Debian systems with a graphical desktop.
- **Python:** install `dikdik-0.2.0-py3-none-any.whl` with Python 3.13+. The wheel
  includes the browser UI; its optional `[desktop]` extra adds the desktop host.

Desktop bundles include Python and matching Chromium. Development toolchains,
Docker, ACP executables and model credentials remain separate. Close an existing
Dikdik desktop before installing the update. The same private data location is
retained; back it up before updating. There is no automatic in-app updater yet.
`SHA256SUMS.txt` covers all uploaded distribution and desktop files.

## Changes

- Native desktop window and platform icons; local first authenticated server.
- Task completion, failures and requests for attention produce native alerts.
  Clicking an alert opens its task. Previews are opt-in; notifications never
  approve commands or submit secrets. Windows registration fixes missing banners.
- The opening logo animates its ears and eyes against faint drifting binary
  digits; reduced-motion preferences disable animation. No startup delay is added.
- Persistent browser sessions support page navigation, input, clicking, keyboard
  actions, scrolling and screenshots. Agent web fetching uses real response data.
- Batched rendering, task navigation and repository lookup improvements.
- Colored terminal output and commands, bounded transcripts and process-tree stop.
- Agent planning, context, provider recovery, local verification and control fixes,
  plus ACP stdio integration.

## Validation and limits

Windows source-desktop browser navigation and inputs were exercised against real
pages. A real offline task produced a visible native notification, and its click
opened the correct task, confirmed by the user. Notification policy, lifecycle,
shortcut registration and all frontend tests passed locally. Release CI repeats
the complete Python/frontend checks and builds the three platform installers
before publishing.

The bundled installers still need end-to-end native installation testing on each
supported operating system. macOS and Linux interaction and notification delivery
have not been verified locally. Binaries are unsigned developer previews, not a
claim of production readiness. See SECURITY.md for execution boundaries.
