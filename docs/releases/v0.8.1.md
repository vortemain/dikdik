# Dikdik 0.8.1 — work on another computer over SSH

## Connect to a host
Open a folder, or a repository, on another computer (a dev server, a cloud VM, a
machine under your desk) and let the agent work there, the way a remote editor window
does. In Code mode, the new **Local** pill in the message box chooses where work runs:
this computer, a live SSH connection, a host from your `~/.ssh/config`, or **Add SSH
connection…**.
- **Uses your own SSH setup.** Keys, ssh-agent, ProxyJump and known_hosts work as in a
  terminal. Dikdik never asks for or stores passwords; a refused key explains how to
  set one up.
- **Host keys are checked.** The first connection shows the host's fingerprint and
  saves it only when you confirm. A changed key stops the connection.
- **Nothing to install by hand.** The host needs Linux or macOS with Python 3.13 or
  newer. Dikdik copies itself into `~/.dikdik-remote` there, starts on the host's own
  loopback address and reaches it through an SSH tunnel. Files, commands, tests, Git
  and model calls all run on the host.
- **Open a repository on a host.** Pick one of your GitHub repositories or paste any
  Git URL; the host clones it with its own Git sign-in and Dikdik opens the clone.
- **A window per host.** The remote window shows `SSH: host` in its title bar and
  message box. Disconnect from there or from this computer; Dikdik stops on the host
  with it.

See [Working on another computer over SSH](../SSH.md) and ADR-009 in
[DECISIONS.md](../DECISIONS.md).

## Updates you don't miss
When a new version is out, Dikdik now recommends it once in a small popup, marks
Settings with a dot, and shows a full **Updates** section in Settings: the version,
the download size, what happens on this platform, the release notes, **Check now**
and **Install**. **Later** skips that version. A new **Check for updates
automatically** switch (on by default) controls the checks at start and every six
hours; checking never installs anything by itself. Contributed by mk-Denver.

## A livelier start
The loading bar is gone: the Dikdik logo turns in 3D while light sweeps across it,
and the name flips in letter by letter. With reduced motion it rests and only the
glyph breathes.

## Fixed
- The agent's task list stayed on its first step after the work was done. Steps now
  advance as the agent works, a follow-up turn sees the open list, and a turn that
  ends with open steps is asked to update them first.
- Benchmark checks on Windows failed to clean up when a test left a server running.
- A Windows test of Stop sometimes failed although the connection had been closed.

## Validation
- Each change passed the full CI suite (Python 3.13 on Windows and Linux, frontend
  typecheck, tests and build, CodeQL and the security scan) in its own pull request
  (#5 to #10).
- The combined release, on Windows with Python 3.13: the frontend typecheck, 258 web
  tests and the build pass, and the committed bundle matches the build. The Python
  suite ran 1,503 tests (9 skipped); one timing-sensitive background-review test
  failed once under the full run and passed on three reruns.
- Connect to host was tested against a stand-in `ssh` that runs the real install,
  server start and `git` clone on the same computer and forwards ports itself. It has
  not yet been tried against a real SSH server.
- The in-app update popup and the boot animation were covered by tests, not watched
  on a release build.

## Upgrading
Nothing to configure. Connect to host needs the OpenSSH client (included in Windows
10+, macOS and Linux).
