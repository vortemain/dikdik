# Dikdik 0.3.0 — desktop polish and in-app updates

A quieter, better-behaved desktop host: no console windows flashing on Windows,
a window that opens maximized instead of minimized, notification sounds on by
default, read-only web fetches that no longer interrupt you for approval, and a
built-in updater that checks for, downloads, verifies and installs new releases
from inside the app.

## Downloads and installation

- **Windows x64:** run `Dikdik-0.3.0-Windows-x64-Setup.exe`. Requires the Microsoft
  Edge WebView2 Runtime. Installs into the per-user Programs directory.
- **macOS:** open the DMG matching its named CPU architecture and drag Dikdik to
  Applications. This preview is not Developer ID signed or notarized; standard
  Gatekeeper restrictions apply. Native notification permission is required.
- **Linux amd64:** install `Dikdik-0.3.0-Linux-amd64.deb` with
  `sudo apt install ./Dikdik-0.3.0-Linux-amd64.deb`. Targets Ubuntu 24.04 and newer
  compatible Debian systems with a graphical desktop.
- **Python:** install `dikdik-0.3.0-py3-none-any.whl` with Python 3.13+. The wheel
  includes the browser UI; its optional `[desktop]` extra adds the desktop host.

Desktop bundles include Python and matching Chromium. Development toolchains,
Docker, ACP executables and model credentials remain separate. Close an existing
Dikdik desktop before installing the update. The same private data location is
retained; back it up before updating.
`SHA256SUMS.txt` covers all uploaded distribution and desktop files.

## Changes

- **In-app self-updater.** On launch, Dikdik checks the latest published release
  against the installed version. When a newer one is available, an "Update"
  indicator appears beside Settings in the sidebar. Click it (or the Updates row
  in Settings → General) to download the installer for your platform, verify its
  SHA-256 against the release `SHA256SUMS.txt`, install it, and relaunch. Network
  access is read-only HTTPS to api.github.com and the release asset host; nothing
  else is exposed.
- **No console window on Windows.** Child processes started by the in-app
  terminal, the agent's Docker shell and test runner, the Git tab, browser
  capture, ACP agents, the formatter and automation events now run with
  `CREATE_NO_WINDOW`, so a command prompt no longer pops up while a command runs.
  Stop/Ctrl-C still works (process groups are preserved).
- **Opens maximized.** The desktop window restores, shows and maximizes on launch,
  so it no longer opens minimized or behind the previous window after the
  launcher exits.
- **Notification sounds on by default.** The completion chime (in the browser)
  and the native desktop alert sound now play by default when a task finishes.
  Toggle them off in Settings → General → Notification sounds.
- **Read-only fetches no longer ask for approval.** In the default "Ask before
  commands" mode, `web_fetch` and `browse_url` (read-only public-web GET and
  navigation) run without a confirmation prompt. Commands and data-sending or
  destructive browser actions still ask; high-risk commands still ask in both Ask
  and Risky modes. "Always" still confirms every non-read-only action.
- Removed the long-task progress dashboard banner that appeared at the top of the
  conversation while a task ran.

## Validation and limits

Windows source-desktop browser navigation and inputs were exercised against real
pages. Notification policy, lifecycle, shortcut registration and all frontend
tests passed locally. Release CI repeats the complete Python/frontend checks and
builds the three platform installers before publishing.

The bundled installers still need end-to-end native installation testing on each
supported operating system. macOS and Linux interaction, notification delivery,
and the new updater's install/relaunch path have not been verified locally on
every platform. Binaries are unsigned developer previews, not a claim of
production readiness. See SECURITY.md for execution boundaries.
