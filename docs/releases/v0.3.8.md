# Dikdik 0.3.8 — a live browser, a real desktop window, and an agent that sets up the computer

The agent's browser is now live in the Browser panel, with the tools to test forms
and designs the way a person would. On Windows the desktop app has one integrated
title bar, the layout holds at every window size, and the sidebar and start screens
are redesigned. The agent also installs and verifies what a project needs on your
computer instead of stopping at "command not found".

## Downloads and installation

- **Windows x64:** run `Dikdik-0.3.8-Windows-x64-Setup.exe`. Requires the Microsoft
  Edge WebView2 Runtime. Installs into the per-user Programs directory.
- **macOS:** open the DMG matching its named CPU architecture and drag Dikdik to
  Applications. This preview is not Developer ID signed or notarized; standard
  Gatekeeper restrictions apply. Native notification permission is required.
- **Linux amd64:** install `Dikdik-0.3.8-Linux-amd64.deb` with
  `sudo apt install ./Dikdik-0.3.8-Linux-amd64.deb`. Targets Ubuntu 24.04 and newer
  compatible Debian systems with a graphical desktop.
- **Python:** install `dikdik-0.3.8-py3-none-any.whl` with Python 3.13+. The wheel
  includes the browser UI; its optional `[desktop]` extra adds the desktop host.

Desktop bundles include Python and matching Chromium. `SHA256SUMS.txt` covers all
uploaded files. Settings → General → Updates installs this release in the
background and reopens Dikdik.

## Changes

- **A live browser.** The Browser panel shows the page live as it changes, so you
  can watch the agent work and take over at any moment. Clicks, double and right
  clicks, hover, typing, paste and scrolling respond at once.
- **Testing like a person.** The agent reads the page as an accessibility tree with
  stable element ids and acts by role, label or text. It types key by key (input
  masks and live validation run), hovers, drags, checks boxes, switches to dark
  mode or a phone size, and zooms screenshots. It can also read the console and
  the data a form actually sent. App previews take up to 20 steps, each with an
  expected result. A failing step is named and captured, and the app stays open
  for step-by-step testing.
- **One title bar on Windows.** The native title bar is gone. Dikdik's own bar
  holds the sidebar toggle, project and task, the Terminal, Browser and Files
  buttons, and the window buttons. Dragging, Snap and double-click to maximize
  work as usual. A maximized window stops at the taskbar, and launch no longer
  flashes green.
- **A layout that holds.** Between 761 and 1100 px wide, opening a panel no
  longer pushes it under the conversation. The sidebar folds to a rail instead.
- **Sidebar and start screens.**
  - **Sidebar:** tasks are grouped by day, with marks for runs that failed or
    need you, and how long ago each was active.
  - **Start screens:** a calm start-up screen, and a welcome page with your
    project, quick starts and your recent conversations.
- **The agent sets up your computer.** `environment_check` reports what your
  project needs (about 40 toolchains, from Python and Node.js to Rust, Java, .NET,
  C++, Flutter, Swift and Arduino), what is missing, and the exact install and
  verify commands for winget, Scoop, Chocolatey, Homebrew or your Linux package
  manager. A failed command comes back with the fix. A tool installed during a
  task works in the next command without restarting.
- **Right-click works again** in the desktop window on Windows, macOS and Linux.
  No console windows pop up on Windows. (Thanks to Mwangi Caroline.)
- **Fixes.** Forms on public pages can submit again; they were always blocked.
  Clicking a link while the page is being read no longer fails.

## Validation and limits

The full Python suite and the frontend tests and typecheck pass on Windows; CI runs
them on Windows and Linux and builds every desktop bundle. The browser actions and
preview steps ran against real Chromium. On a real Windows window, the title bar
removal, the maximized size against the taskbar and closing were measured. The
setup diagnosis ran through Dikdik's own command runner on Windows; no install was
run by the agent during validation. macOS and Linux keep their native title bars.
Binaries are unsigned developer previews, not a claim of production readiness.
Local mode runs commands with your user's rights, including installs you approve;
see SECURITY.md.
