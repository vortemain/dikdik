# Dikdik 0.3.7 — fast, live previews of your app

Previewing the app the agent builds no longer hangs for minutes. The dev server
keeps running after a preview, and the Browser panel shows your app live, with
its full address, Reload, Desktop/Mobile and "Open in your browser".

## Downloads and installation

- **Windows x64:** run `Dikdik-0.3.7-Windows-x64-Setup.exe`. Requires the Microsoft
  Edge WebView2 Runtime. Installs into the per-user Programs directory.
- **macOS:** open the DMG matching its named CPU architecture and drag Dikdik to
  Applications. This preview is not Developer ID signed or notarized; standard
  Gatekeeper restrictions apply. Native notification permission is required.
- **Linux amd64:** install `Dikdik-0.3.7-Linux-amd64.deb` with
  `sudo apt install ./Dikdik-0.3.7-Linux-amd64.deb`. Targets Ubuntu 24.04 and newer
  compatible Debian systems with a graphical desktop.
- **Python:** install `dikdik-0.3.7-py3-none-any.whl` with Python 3.13+. The wheel
  includes the browser UI; its optional `[desktop]` extra adds the desktop host.

Desktop bundles include Python and matching Chromium. `SHA256SUMS.txt` covers all
uploaded files. From 0.3.6, Settings → General → Updates installs this release in
the background and reopens Dikdik.

## Changes

- **Previews that work.** The preview proxy closed connections after 20 quiet
  seconds while `next dev` was still compiling the page, and the preview browser
  closed the dev server's live-reload socket, which made Next reload the page in a
  loop. Both are fixed for your own app (public pages keep their limits), the page
  is compiled before the browser opens it, and forms and server actions reach the
  app. A Next.js shop that failed after about five minutes per attempt now
  previews in 29 seconds.
- **Your app, live in the Browser panel.** The dev server keeps running after a
  preview; the panel shows the real page at `localhost:port`, with Reload,
  Desktop/Mobile, a working "Open in your browser", Stop, and paths typed in the
  address bar. The next preview of the same dev server starts at once; a
  production server is restarted so you never see an old build. The app runs on
  a different host name from Dikdik and never receives Dikdik's sign-in cookie.
- **No leftover servers.** On Windows, dev servers end with Dikdik's process, even
  when it is killed or closes for an update; the updater stops previews first.
- **Faster on Windows** for dev servers that listen only on IPv6 (Vite): about two
  seconds less per request.
- **Releases** are now published as full releases and marked Latest on GitHub.

## Validation and limits

The full Python suite and the frontend tests and typecheck pass on Windows; CI runs
them on Windows and Linux. The preview fixes were measured on a real Next.js
project, and the live panel was checked in a browser against a scripted stand-in
model. The live view was not yet checked inside the packaged desktop window on
each operating system. Binaries are unsigned developer previews, not a claim of
production readiness. Local mode runs commands with your user's rights; see
SECURITY.md.
