# Dikdik 0.3.2 — sponsored access, desktop fixes and a reliable updater

This release ships the invite-only sponsored inference gateway for the Nebius
hackathon, restores the desktop right-click context menu, fixes the in-app updater
so it finds the latest published release, and resolves a Windows cleanup race that
caused intermittent CI failures.

## Downloads and installation

- **Windows x64:** run `Dikdik-0.3.2-Windows-x64-Setup.exe`. Requires the Microsoft
  Edge WebView2 Runtime. Installs into the per-user Programs directory.
- **macOS:** open the DMG matching its named CPU architecture and drag Dikdik to
  Applications. This preview is not Developer ID signed or notarized; standard
  Gatekeeper restrictions apply. Native notification permission is required.
- **Linux amd64:** install `Dikdik-0.3.2-Linux-amd64.deb` with
  `sudo apt install ./Dikdik-0.3.2-Linux-amd64.deb`. Targets Ubuntu 24.04 and newer
  compatible Debian systems with a graphical desktop.
- **Python:** install `dikdik-0.3.2-py3-none-any.whl` with Python 3.13+. The wheel
  includes the browser UI; its optional `[desktop]` extra adds the desktop host.

Desktop bundles include Python and matching Chromium. Development toolchains,
Docker, ACP executables and model credentials remain separate. Close an existing
Dikdik desktop before installing the update. The same private data location is
retained; back it up before updating.
`SHA256SUMS.txt` covers all uploaded distribution and desktop files.

## Changes

- **Sponsored inference pilot.** `python -m dikdik.sponsored_gateway` runs an
  optional invite-only proxy to Nebius with a fixed NVIDIA Nemotron model. It
  authenticates by invitation, enforces daily per-user and global allowances,
  supports a separate judge allowance pool, and exposes a `/healthz` check.
  Configurable bind host and usage DB path allow container deployment behind an
  HTTPS reverse proxy. `--check-env` diagnostics report which variables reached the
  process without printing secret contents. The user needs no Nebius key; the
  service owner pays. When the allowance ends, Dikdik never switches to a billable
  key on its own. Tavily always uses the user's own session key.
- **Desktop right-click context menu.** pywebview 6 gates the native context menu
  on debug mode, so copy/paste/select by right-click was unavailable in release
  builds. Dikdik now restores the default WebView2 context menu without enabling
  devtools or F12.
- **In-app updater finds the latest release.** The updater queried GitHub's
  `/releases/latest`, which ignores prerelease-flagged releases and returns 404 when
  every release is a prerelease. It now reads the releases list, skips drafts, and
  selects the newest entry that carries a platform installer. Users can now see and
  install 0.3.x preview builds.
- **Windows cleanup race.** Background shell drain threads are now joined in
  `close()`, so the OS releases the killed process's working-directory handle before
  project snapshot or temp-directory cleanup runs. This fixes an intermittent
  `PermissionError [WinError 32]` on Windows.
- **MCP test collection.** The upstream `test_server` helper is imported through the
  module, so pytest no longer collects it as a test and fails on its missing fixture.

## Validation and limits

The full Python suite (875 tests) and frontend checks passed on Windows and Linux.
The sponsored gateway, desktop context-menu hook, updater release selection, and
background-shell cleanup join are each covered by dedicated tests. The bundled
installers still need end-to-end native installation testing on each supported
operating system. Binaries are unsigned developer previews, not a claim of
production readiness. See SECURITY.md for execution boundaries.
