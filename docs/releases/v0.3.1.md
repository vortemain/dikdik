# Dikdik 0.3.1 — autonomous workflow and browser verification

This update reduces approval interruptions, removes repeated verification work,
and makes the agent carry executable tasks through relevant checks.

## Changes

- **Auto by default.** The composer migrates its old implicit Ask setting once.
  Auto runs authorized tools without per-action approval prompts, including when
  resuming older conversations. Explicit permission rules and project trust remain
  authoritative; Ask, Plan and Classic modes remain available.
- **Complete the requested work.** The agent is directed to execute available
  commands itself, recover missing dependencies for verification requests, and
  report concrete blockers. Repeated command handoffs, redundant permission
  questions and unsupported completion claims no longer count as finished work.
- **Test without artificial edits.** Requests to test existing software can finish
  with recorded verification and no source changes. Syntax alone cannot satisfy an
  explicit test/build verification request.
- **Local UI verification.** A supervised preview server and isolated Chromium
  session check desktop/mobile rendering and supplied interactions with expected
  visible results. Diagnostics include JavaScript errors, failed resources and
  horizontal overflow; screenshots are saved to task history. The server and
  preview browser stop afterwards. Only the assigned loopback port is accessible
  through the reserved preview hostname; ordinary browsing stays public-only.
- **Checks suited to the request.** Design/build requests include relevant
  declared type, lint and build checks alongside tests. Requested interactions
  require behavioral evidence rather than screenshots alone.
- **Less wasted work.** Successful current verification is reused until an edit
  or command invalidates it. Completion replies trigger host checks without extra
  model reminders. Small revision signatures replace per-tool serialization of
  the project for loop detection.
- **More reliable persistence.** Atomic transcript saves retry brief Windows
  sharing locks. Cancellation results no longer carry misleading next-step hints.

## Validation

Local validation covered workflow ownership, permission policy, dependency
recovery, verification caching, engine dispatch, local execution, resume, context
continuity and cancellation. All 166 frontend tests, TypeScript checking and the
web build passed. Real Chromium fixtures verified successful interactions and
desktop/mobile rendering, detected a deliberately broken UI, and confirmed preview
server cleanup. Release CI repeats the complete Python/frontend suites and builds
the platform packages before publication.

## Downloads and limits

Use the installer matching your platform: Windows x64, macOS arm64/x86_64 or Linux
amd64. The portable wheel requires Python 3.13+. Desktop installers bundle Python
and Chromium; project toolchains and model credentials remain separate. Close
Dikdik before installing the update. Existing project data is retained.
`SHA256SUMS.txt` covers the uploaded distribution and desktop assets.

These remain unsigned developer-preview builds. Browser checks cover the supplied
page and actions; they do not prove aesthetic quality or every user journey.
Native installation and update/relaunch behavior still require testing on each
supported operating system. Agent reasoning quality also depends on the selected
model. See SECURITY.md for execution boundaries.
