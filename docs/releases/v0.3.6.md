# Dikdik 0.3.6 — software from an idea, a live Files panel, and updates that just work

The agent now decides how to build what you ask for: a website, web app, mobile
app, API, desktop app or CLI each get the stack they need, with a real backend
even when you have no database credentials. The Files panel follows the agent
as it writes, the preview no longer loops, and desktop updates install silently
and reopen the new version.

## Downloads and installation

- **Windows x64:** run `Dikdik-0.3.6-Windows-x64-Setup.exe`. Requires the Microsoft
  Edge WebView2 Runtime. Installs into the per-user Programs directory.
- **macOS:** open the DMG matching its named CPU architecture and drag Dikdik to
  Applications. This preview is not Developer ID signed or notarized; standard
  Gatekeeper restrictions apply. Native notification permission is required.
- **Linux amd64:** install `Dikdik-0.3.6-Linux-amd64.deb` with
  `sudo apt install ./Dikdik-0.3.6-Linux-amd64.deb`. Targets Ubuntu 24.04 and newer
  compatible Debian systems with a graphical desktop.
- **Python:** install `dikdik-0.3.6-py3-none-any.whl` with Python 3.13+. The wheel
  includes the browser UI; its optional `[desktop]` extra adds the desktop host.

Desktop bundles include Python and matching Chromium. `SHA256SUMS.txt` covers all
uploaded files.

**Updating from 0.3.5 or earlier:** the update is carried out by the version you
have installed, so this one time the setup wizard may appear (0.3.5's updater
used the wrong silent flag). The new installer closes the running Dikdik for
you. From 0.3.6 on, updates download in the background and install silently.

## Changes

- **From an idea to working software.** For a new project (or a request for a
  website, mobile app, API, desktop app, CLI and the like) the agent first works
  out who uses it, on what, its data, integrations and realtime, offline or SEO
  needs, then chooses the architecture: Astro for content sites, Next.js or
  Vite + React for web apps, Expo for mobile, Hono, FastAPI or Go for APIs,
  Tauri for desktop, Go, Rust or Python for CLIs, Python with uv for data and AI.
  Your stack, or the project's, always wins. It records the full feature list as
  requirements and proves the result runs.
- **A real backend without credentials.** PGlite (real PostgreSQL in-process),
  SQLite, in-memory MongoDB and Redis, and local adapters for email, storage and
  payments behind the production interfaces; migrations, seed data and an
  `.env.example`, so going live is configuration only.
- **Knows your machine.** The agent is told which runtimes and package managers are
  installed and which of PostgreSQL, MySQL, MongoDB and Redis are running; bun is
  preferred when installed unless the project's lockfile says otherwise.
- **Preview fixed.** `path: "."` or a file name is understood, static sites need no
  server command, literal ports and bare `bun run dev` / `npm run dev` get the
  assigned port, and servers can no longer be started in the background with
  run_command (each attempt used to hang for a minute on a new port).
- **Live Files panel.** Each create and edit reaches the folder at once; the Explorer
  shows new files as they are written, opens or reloads the file being changed,
  and marks files U, M or D with folder dots, as in VS Code. Files, Terminal and
  Browser stay open across tasks.
- **Desktop updates.** Background download with progress and Cancel, required
  checksum, release notes in Settings, a prompt when tasks are running, and a
  per-platform install after Dikdik exits: silent Inno Setup on Windows, a
  signature-safe bundle swap on macOS, `pkexec apt-get` on Linux; pip installs get
  the upgrade command. The next launch says whether the update took effect.
- **Settings** scrolls in one place; the blank space below the dialog is gone.

## Validation and limits

The full Python suite and the frontend tests and typecheck pass on Windows; CI runs
them on Windows and Linux. The Files panel and the update screens were checked in
the browser against a scripted stand-in model and simulated update states. The
new install hand-offs were syntax-checked but not yet run end to end on each
operating system, and the stack guidance has not yet been measured with live
models. Binaries are unsigned developer previews, not a claim of production
readiness. Local mode runs commands with your user's rights; see SECURITY.md.
